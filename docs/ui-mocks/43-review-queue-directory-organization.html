Vivi · Review queue exploration

Keep the queue fast. Restore where each file lives.

The queue currently optimizes each row for the file itself. That works inside one directory, but a mixed workspace makes the user repeatedly reconstruct path context. These concepts use the same queue data and vary only how directory identity organizes it.

The product job

Move through attention items quickly, while knowing which authored area is being reviewed before opening the document. “Next queued” remains global in every concept.

Directory is context, not status Queued, In Review, and Reviewed remain the lifecycle. Paths only organize items inside those states.
Show only useful branches Roll up directories that contain attention items. Never reproduce the entire repository tree inside the inspector.
Global queue stays authoritative Grouping cannot strand urgent feedback. Open threads and unseen work still determine the next item.

Comparison behavior

What becomes visible
  • Useful parent/child relationships
  • Roll-up file counts
  • Collapsed low-priority branches
Deliberate boundary

Only queue-bearing branches appear. Single-child directory chains may compress into one row, so this never becomes a second full repository tree.

What this optimizes

Long sessions can be completed area by area, reducing context switching when several generated document sets change together.

What becomes visible
  • Current review scope
  • Local progress per area
  • Short path prefixes inside the set
Tradeoff

“Working set” becomes a new concept with selection state. It may over-formalize a queue that should otherwise feel immediate.
