# For you — 右インスペクターの仕様

Status: Implemented; covered by Storybook, domain/adapter tests, and end-to-end tests. Product UI copy is English. The approved panel name is **For you** (2026-09-06).

Reference: `docs/ui-mocks/52-now-reading.html`.

## 目的

「いま確認する意味があるファイルが、しばらく置かれる場所」。
左は永続的な文書の地図、中央は読む場所、右は直近の動きと受け渡し途中の意図。
件数をゼロにすることを目的にしない。既存の product thesis を具体化する提案。

## 構成

- Review queue を **For you** に変更。**Document** タブは維持する。
- All / Unseen / Drafts / Changed と Next queued は廃止する。
- **Feedback** と **Recent** の2セクション。空のセクションは見出しごと省く。
- ファイルは一度だけ表示。両方に該当する場合はフィードバックに置く。
- 主ラベルは実ファイル名、補助ラベルはH1。名称が重複する場合は親パスも示す。
- 理由と相対時刻を1行で添える。ファイル形式バッジ、常時の進捗、完了チェックは不要。
- フィードバックは淡い点で区別。「エージェント未読」「下書き」と明示し、誰の未読かを曖昧にしない。
- 両方を持つ場合は「下書き1件 · エージェント未読2件」。件数はメッセージ総数ではなく対象スレッド／下書き数。

## 表示の判定

| 理由                                     | 有効期間 | 時刻の起点                              |
| ---------------------------------------- | -------- | --------------------------------------- |
| 内容が更新された                         | 30分     | 実際の内容変更の時刻                    |
| 人が文書を明示的に開いた                 | 30分     | 選択・タブ切替などの明示的な閲覧開始    |
| エージェントが意図的に提示した           | 30分     | 対象サーバーが提示を受け付けた時刻      |
| エージェントが公開フィードバックを読んだ | 30分     | 最新メッセージに対する最初の既読        |
| 有効な公開フィードバックが未読           | 期限なし | 最新の人のメッセージ                    |
| 下書き／未保存の入力がある               | 期限なし | 最後の編集。保存してもPublishまでは維持 |

各ファイルの最新の有効イベントを使う。30分ちょうどで最近の対象外。
未読／下書きがあるファイルは時間を超えて残る。内容を読んだ状態と修正完了は別。
受動的な inbox、同じメッセージの繰り返し既読、タブ復元、再接続、HTTP取得、
描画、スクロール、Gitスキャンだけでは延長しない。新しい公開メッセージは再び未読。

現在読んでいる文書も、時間が経てば右側から退いてよい。中央のタブを閉じたり移動したりしない。
最近の行は「今は隠す」で一時的に退けられる。新しい内容変更・明示的な閲覧／提示で再表示。
隠した状態は古いイベントの再取得では解除しない。未読／下書きはこの操作の対象外。

## 並び順と操作

フィードバックを上に、最近を下に置き、それぞれ意味のある最新イベント順。
既読になったファイルは最近へ移る。すべて古ければ静かな空状態だけを示す。
単クリック／Enterでプレビュー、ダブルクリックでタブ保持。既存の読書操作に揃える。
更新は即時反映するが、行にポインターやキーボードフォーカスがある間は並び替え・削除を保留。
現在のスクロール位置を保ち、新着のために先頭へ飛ばさない。並び順の同時刻はパスで安定化。
エージェントの提示を他のブラウザーの強制ナビゲーションにしない。

## 起動前の変更とGit

起動時に30分の窓を復元する。起動した時刻に全ファイルを「更新」にしない。

1. Gitの作業ツリーで変更／追加された文書は、ファイルのmtimeが直近30分なら候補。
2. 最近30分の現在のHEADから到達可能なコミットで内容が変わった文書も候補。
   コミット時刻を使い、差分で判定する。古いクリーンなファイルのcheckout時mtimeだけでは載せない。
3. 起動後は内容ハッシュとwatcherを主とし、保存し直しただけの同一内容は延長しない。
4. 削除ファイルは通常の文書行にしない。名前変更は現在のパスに統合し、元パスの行を重複させない。
5. Gitがない場合は、対象文書のmtimeによる初期候補とwatcherを使う。

mtimeは起動前の変更時刻の近似。コピーなどでも変わり得る。コミット時刻も実編集時刻の近似。
単にローカルにfetchされた時刻は使わない。取得できない時刻は現在時刻で捏造しない。
Git列挙は期限／件数を制限し、利用不可でも閲覧を止めない。部分取得は状態詳細で説明する。
古い未コミット差分はChangesから見られるが、それだけでは右側に居続けない。

## 文書の範囲と旧データ

右側にも選択ルート、include/exclude、無視ディレクトリー、安全なパス制約を適用。
既定ではMarkdown／HTML。ユーザーが明示的にCSSをincludeした場合はCSSも対象になる。
対象外CSS、削除済みファイル、旧パスのコメントは通常一覧や未読件数から除外する。
記録は削除せず「対象外のフィードバック」として状態詳細に折りたたむ。
下書きも黙って消去せず、その場所から確認できるようにする。

旧resolved／archivedは読み取り互換として保持し、現在の未読判定から除外する。
UIとCLIは同じ有効スレッド集合とメッセージ単位の既読判定を使う。
ファイル内の別スレッドの既読を、未読スレッドの既読として表示しない。
設定データの消去や旧コメントの書き換えを解決策にしない。

## エージェントopenと共有

`vivi open` は共有提示イベントを記録する。
標準のopenでは対象を検証し、サーバーが提示イベントを記録してからURLを開く。
ブラウザーの起動に失敗した場合は手動リンクを返し、提示された状態とは区別してエラーを伝える。
`--print` はURL生成のみで活動を記録しない。ホストブラウザーを使う場合は、
そのリンクで実際に文書を開いた際にサーバーへ活動を記録する。単なるリンク作成は提示に数えない。
actorを信頼できる形で渡せない場合は「開かれた」と表示し、Codex／Claudeと推測しない。

活動はブラウザーごとのlocalStorageだけに置かず、ワークスペース単位で保持する。
同じルートの複数サーバーにも通知／再同期し、再起動や新しいタブでも同じ30分窓になる。
表示から退いても履歴は必要な範囲で保持。自動ポーリングや再接続で活動時刻を増やさない。

## モックの範囲と次の検証

モックは代表的な文書行・2分類・既読移動・時間経過・提示・非表示・空状態を再現。
Git・共有保存・actor判定・入力中のフォーカス保持は接続していない。
単一案に絞ったのは、ユーザーが方向を指定し最終判断を委任しているため。

次は承認された構成のStorybook facadeを作る。代表playは時間境界、複合理由、
既読後の移動、非表示→新イベント、キーボード選択、フォーカス中の移動抑制、空状態。
実装時はGit起動前変更、旧アーカイブ、対象外CSS、複数サーバー同期、
`--print`無活動と実open活動、再起動後の期限維持を回帰テストで固定する。

## English UI copy

- Panel: For you / Document
- Groups: Feedback — Awaiting handoff; Recent — Last 30 minutes
- Reasons: Unread by agent; 1 draft / N drafts; Input in progress; Updated; Opened; Presented by agent; Read by agent
- Dismissal: Hide for now
- Empty: Nothing to look at right now. Updated and opened documents will appear here for a while.

Git history is bounded to 64 recent reachable commits and the existing Git timeout. Activity logs project the last 30 minutes across servers using the same workspace data directory.
