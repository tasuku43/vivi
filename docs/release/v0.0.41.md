# v0.0.41 — Faster large workspace search

- Stream content search through a reusable buffered reader, avoiding whole-file
  loads, split-line copies, and per-line lowercased strings.
- Reduce large workspace traversal and startup reconciliation work by using
  directory-entry metadata, avoiding redundant path resolution and sorting,
  and checking exclusion paths without allocating segment slices.
- Reuse the existing filename metadata cache for content search when it is
  already available. Search still reads current file contents; it does not
  retain content or build a new index on a cold query.

On the 93,696-file Linux source tree, measured on macOS arm64 with Go 1.26.7,
cold content search improved from 1,355 ms to 300 ms per query, with total
allocation dropping from 726.1 MB to 105.6 MB. Startup reconciliation improved
from 1,048 ms to 249 ms, with total allocation dropping from 508.5 MB to
66.6 MB. Cold content search still walks the workspace; warm searches can reuse
the existing filename metadata cache.
