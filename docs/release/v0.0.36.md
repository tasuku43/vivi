# v0.0.36 — Reader UX and focused agent feedback

Vivi now gives documents more space and keeps navigation, status and feedback
controls quieter while preserving the path from human review to agent input.

## Changes

- Show document H1 beneath the real filename in the tree, with folder icons and
  hierarchy guides. Use one selected-file background and quiet ancestor markers.
- Simplify tabs, document view switching, search results, review queue signals,
  reading guidance and workspace status details.
- Keep passive rendered comment markers in the margin and emphasize the target
  when its thread is open or being composed.
- Load local image dependencies without adding them to the document-only tree.
  Image-only Markdown and HTML blocks support publishing and reopening feedback.
- Preserve a newer Close or Save action when an earlier resume request completes
  late, keeping saved feedback accessible and unsaved text available to resume.
- Recover the current document and refresh missed workspace changes when a local
  server reconnects, without reopening tabs or dropping the user's input.
- Reduce the CLI to launch, `servers` and `inbox`. Passive reads preserve unread
  state; `--read-as codex|claude` records an explicit read receipt.

The performance harness now measures the supported passive inbox command
(schema version 4, `cli_inbox`) instead of the removed review queue command.

## Dependency security

- Update the build-time Browserslist dependency to 4.28.9 and its browser data;
  the lockfile passes npm audit with no reported vulnerabilities.
- Update gRPC-Go to 1.83.1 for GHSA-vp52-pcj8-j9qc.
- Update Goldmark to 1.7.17 for GO-2026-5320, found by the pre-release Go
  vulnerability scan. The updated dependency graph passes govulncheck.

## Compatibility

The former `comments`, `review`, `reply`, `claim` and `release` commands and
their task lifecycle APIs have been removed. Use `vivi servers` and
`vivi inbox <url> [--read-as codex|claude] [--json]`; use filesystem and Git tools
in the coding workspace for implementation work. The browser Changes view remains.

Local image preview still enforces root confinement, explicit excludes, ignored
directories and file size limits. Standalone SVG responses disable scripts with
a sandbox CSP. HTML authored scripts remain opt-in.

## Pre-release user journey verification

A separate Git-backed fixture workspace was used; the user's feedback was not
modified.

- Launch the Go binary with product defaults and discover its ready URL.
- Find Markdown from first use, preview it, keep a tab, follow a local HTML link,
  open the outline, search updated text, and inspect source and Changes.
- Save a rendered comment, confirm that passive CLI intake is empty, reload the
  browser, publish, retrieve the file/anchor/body with the CLI, explicitly read
  as Codex, and confirm Seen plus the reader identity in the browser.
- Update the document externally and add a file: verify live content, H1, outline,
  tree, text search and Git Changes.
- Inspect light and dark/system rendering.
- Stop and restart the server: verify disconnected/live status, persisted
  feedback and automatic recovery of the active document and offline changes.
  This found a stale preview-error state, now fixed and covered by an E2E
  that failed before the repair.
- Exercise Markdown and HTML local-image feedback through saved-draft reload,
  publication, passive intake and explicit read receipt in the canonical Go E2E.
- Run the full suite, covering narrow layouts, split panes, keyboard focus,
  stale/resumable inputs, failed-save recovery, deletion, sandboxing and path
  guards in addition to the happy path.

The release operator must also confirm main CI, all four platform archives,
checksums, provenance, the downloaded binary's version and the Homebrew update
PR as described in [releasing.md](releasing.md).

Local verification completed on 2026-09-06: `task check` passed with 492
unit/application/adapter tests, 69 E2E tests, 88 screenshot comparisons, all Go
tests and the UI/Go/Storybook builds. `task storybook:test` passed 88 interactions
with 2 existing skips. `task generate:graphql` and `git diff --check` also passed.

The CI-sized performance profile passed without changing its thresholds: all
15 burst updates and 30 agent-storm paths were observed, with zero missing paths;
three passive inbox calls took 45 ms in total on the local verification run.

A delayed-response E2E also reproduces and guards against a closed input being
reopened by an earlier resume request. Close and Save invalidate that request;
preserved text remains available through an explicit new Resume action, and
saved Source feedback remains accessible through its marker after the composer closes.
