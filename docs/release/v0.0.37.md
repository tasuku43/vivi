# v0.0.37 — Open artifacts for human review

Vivi now opens a document on a selected running server and provides matching
review workflows for Codex and Claude Code.

## Changes

- Add `vivi open <url> [path] [--print]`. Paths are relative to the selected
  server's workspace root. The command validates the target before opening its
  reader URL; `--print` returns the validated link for host browsers and handoffs.
- Reject missing, directory, ignored and outside-root targets before browser
  launch. Encode document names safely, including Japanese text and URL symbols.
- Update both Vivi plugin packages to 0.2.0 with `open` and `apply-feedback`
  skills. Reuse the selected server across opening, feedback intake and re-review.
- Record Seen for explicit apply requests, keep inspection-only requests passive,
  check already-satisfied feedback, and return document links after verification.

This adds no server lifecycle protocol or navigation broadcast to other tabs.
Existing launch, discovery and inbox commands remain compatible. Plugins require
this release's CLI for document opening; plugin installation does not install
or upgrade the Vivi binary.

## Verification

- `task check`: 494 unit/application/adapter tests, 72 E2E tests, 88 screenshot
  comparisons, all Go tests, architecture checks and UI/Go/Storybook builds passed.
- Browser journeys cover CLI links to Markdown and HTML, private drafts,
  publication, Codex/Claude Seen receipts, encoded nested filenames and live
  document updates.
- Codex plugin schema and all four skill packages pass validation.
- Claude Code itself was unavailable locally; its package and CLI/browser
  handoff were verified, but execution inside that host was not tested.
